# AutoDy 隐私与安全设计

适用版本：AutoDy 1.4.2 预发布工作树。本文描述现有本地边界和已验证的发布控制；它不声称 AutoDy 已完成代码签名、外部安全认证或对所有平台风险的覆盖。

## 1. 本地执行边界

AutoDy 的 Dashboard、API、调度器、托盘和受管浏览器自动化运行在用户的 Windows 设备上。管理台仅通过 127.0.0.1:<selected-port> 访问本机服务，动态端口也只在本地回环地址上使用。产品不以文档或发布包为渠道收集真实账号、目标、消息、Cookie、浏览器资料、头像缓存或备份内容。

这一边界不意味着任何本地数据都天然安全：运行时资料仍受当前 Windows 用户权限、设备加密、恶意软件、错误共享和本地备份策略影响。用户应使用受保护的操作系统账户，并避免把运行时目录复制到公开位置。

## 2. 浏览器资料与账号隔离

默认配置将受管浏览器资料放在配置相对的 data/browser-profile。多账号管理将每个账号的受管浏览器资料放入相应账号目录，降低不同账号会话彼此混用的风险。AutoDy 的公开资料 API 使用受限 payload，测试验证其不返回私有标识；头像等缓存通过受控本地端点提供，而不是暴露浏览器 profile 文件。

登录、注销和页面异常均受浏览器锁与身份检查保护。正常开发、测试、诊断和文档验收不得在真实 Douyin 编辑器中输入、粘贴、准备或发送内容。仅限用户明确发起的受控干跑仍需要锁、稳定会话 ID、显示名称、空编辑器和无附件条件，且不调用发送管道。身份歧义、草稿、附件、清理异常或任何可能发送的状态都必须停止。

## 3. 运行时数据、导出与日志

MSI 将程序安装到程序目录，例如 D:\AutoDy 或 %LocalAppData%\Programs\AutoDy；可写数据固定在 %LocalAppData%\AutoDy。portable 和源码安装则由配置目录下的 data 承载可写文件。程序目录与数据目录分离使升级、修复和卸载能够更新 payload 而不擅自删除历史、计划、浏览器资料或备份。

诊断导出、备份与日志是高风险边界。当前 API 设计和测试明确排除浏览器资料、Cookie、头像缓存、发现数据及发送消息正文；发布诊断应使用脱敏摘要。排障时不得把完整 data 目录、浏览器 profile、认证文件或原始日志直接提交到 Git、附在 issue 或复制到聊天工具。

## 4. Git、构建与发布包排除

Git 工作树不得提交 data、.venv、node_modules、日志、缓存、模块注册表、浏览器资料或私有截图。portable 与 MSI 构建使用明确 allowlist，而不是递归复制仓库；这可减少临时输出、测试夹具和运行时资料被意外带入发行物的风险。官方模块包也由受控输入生成并由 manifest/哈希校验。

发布流程会检查候选目录、manifest、允许文件、路径和内容隐私规则。若 CI 的发行检查失败，保留的是用于诊断的受控隐私报告，而不是可公开的运行时资料。任何报告在共享前仍应遵守最小披露原则。

## 5. 服务身份、端口冲突与进程保护

托盘不会因为某个进程监听 8765 就结束它。它先查询 /api/service-identity 与模块信息，再核对 PID、当前 Windows 用户、应用版本、项目/包路径和 Python 解释器。只有通过这些检查的 AutoDy 服务可被复用，且仅经托盘确认管理的服务可在“退出并停止”或重启时停止。

若 8765 由无关监听者占用，AutoDy 在 8766–8799 内选择空闲端口，并可持久化选中端口后在下次启动重新验证。已完成验证表明无关监听者会保持存活，重复启动会复用同一 AutoDy PID。该策略避免了按进程名或端口号进行粗粒度终止的安全风险。

## 6. 包完整性与供应链控制

MSI、portable 和发布 manifest 都使用 SHA-256。用户应将下载文件的 Get-FileHash 结果与同名 sidecar 比较；工程构建会验证固定 Python、依赖、模块包和允许的发行输入。MSI 构建使用受控 Release 配置及可重复构建检查，已有字节级可重复性验证证据。

AutoDy 当前不声称 MSI 已代码签名。未签名安装包可能触发 Windows SmartScreen 或企业策略提示，用户应通过正式 Release、SHA-256 和组织内部可信分发渠道验证来源。不得用打包器、UPX、规避安全软件、绕过 Defender 或隐藏载荷来解决这些提示；这些做法会降低可审计性并增加误报与供应链风险。

## 7. 当前限制与维护要求

本地执行不能取代系统账户保护、磁盘加密、终端防护和用户的安全操作。浏览器自动化仍受平台页面变化、登录有效期和网络环境影响；安全停止优先于自动恢复。端口范围有限，所有候选端口均不可用时服务应失败而非抢占端口。最终 v1.4.2 Release CI 尚待完成，不能把预发布验证当作公开发布证明。

维护人员在变更安装路径、端口发现、日志导出、包清单、模块 ZIP 或浏览器资料处理时，必须同时更新本文件、测试与验收报告和维护指南，并重新执行对应的隐私与完整性检查。
