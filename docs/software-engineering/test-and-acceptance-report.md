# AutoDy 测试与验收报告

适用版本：AutoDy 1.4.2 预发布工作树。本报告只记录已完成测试或已确认本地验证的证据。v1.4.2 最终 Release CI 尚未通过，因此不得据此宣称版本已发布。

## 1. 测试目标与环境

测试目标是验证本地服务、前后端、浏览器安全边界、MSI/portable 打包和发行物隐私边界在当前工作树中可重复检查。自动测试使用项目 .venv、假页面、临时目录或封装输入；不输入、准备、粘贴或发送真实 Douyin 消息。MSI 生命周期验证应在干净 Windows 用户配置下运行，避免干扰现有安装和运行时数据。

测试分为 Python 单元/API、前端组件、MSI 打包、发行物隐私与确定性、安装生命周期、端口/服务复用和手动只读 UI 验收。每类测试回答不同问题：单元测试验证逻辑分支，生命周期验证 Windows Installer 行为，隐私扫描验证发布输入，端口测试验证无关进程不会被误伤。

## 3. 验收项目说明

**Python 与前端。** 后端测试覆盖服务身份、模块元数据、任务状态、安全重试、已解决状态、资料 API、备份与诊断排除等行为。前端测试覆盖页面组件和已暴露的状态。上述数字来自完成的验证记录；本次没有重跑完整应用套件，以免将文档任务扩大为产品回归任务。

**MSI 与 portable。** MSI 打包测试检查生成输入、WiX 目录模型、固定运行时、Release 命名、清单与 hash。生命周期脚本进一步验证首次安装、目录向导取消、修复、默认与自定义程序目录、v1.4.1 到 v1.4.2 主版本升级、卸载、快捷方式和数据保留。portable 与官方模块 ZIP 使用受控排序、时间戳和 LF 规则，支持确定性输出检查。

**服务与端口。** 托盘的聚焦测试检查单实例、身份验证、无关 8765 监听者保护、8766 回退、持久端口重用和仅停止受管理服务。本次运行 tests/test_tray_controller.py 与 tests/test_msi_packaging.py，结果为 23 passed in 1.66s，不涉及安装器生命周期或真实浏览器操作。

**Release 安全。** 发行物验证检查 manifest、SHA-256、允许文件清单、模块包和隐私排除。CI 在包失败时保留经脱敏的隐私诊断，便于定位问题；这不意味着可以收集账号、消息、Cookie 或浏览器资料。

## 4. 验收条件与发布门禁

v1.4.2 的发布前条件包括：干净源码 bootstrap/doctor 成功；后端与前端回归通过；前端生产构建和 portable/MSI 构建通过；MSI 生命周期脚本使用已验证 v1.4.1 基线完成升级；发行物 manifest、SHA-256 和隐私扫描通过；动态端口和服务复用证据仍适用；以及最终 Release CI 成功。

当前唯一明确的发布状态是“prepared, not published”。最终 Release CI 是未解除的门禁。没有该 CI 结果时，不应创建 v1.4.2 标签、GitHub Release 或将候选文件交付为正式版本。

## 5. 已知未覆盖区域

本报告不宣称所有 Windows 版本、权限策略、网络代理、第三方安全软件或平台页面变更均已验证。未签名 MSI 的 SmartScreen/企业策略体验不在现有自动化断言中。真实账号、真实目标、真实消息和真实浏览器 profile 不属于自动测试或验收输入；因此与真实登录状态相关的问题仍需在用户控制下、按安全边界进行只读诊断。

未来若增加浏览器自动化能力、安装器签名或新的发布渠道，必须新增针对性测试和文档，不得把它们追溯性写成 v1.4.2 已验证功能。
