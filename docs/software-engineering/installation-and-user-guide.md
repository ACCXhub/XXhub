# AutoDy 安装与使用指南

适用版本：AutoDy 1.4.2 预发布工作树。v1.4.2 已准备但尚未发布；请以正式 Release 的 MSI、portable 包及同名 SHA-256 文件为准，不要把源码归档当作安装器。

## 1. 系统要求与包类型

AutoDy 面向 Windows x64。MSI 是推荐的普通用户安装方式：它包含固定 Python 运行时、固定依赖和 Chromium，不要求用户预装 Node.js 或 Python。portable 包适用于需要可移动部署的技术用户：它已包含生产前端，但仍需要 Python 3.11 和网络以恢复依赖；它不是“解压即含完整运行时”的 MSI 替代品。源码仓库用于开发，需要项目 .venv、Node.js、PowerShell 5.1 或更高版本；构建 MSI 还需要 .NET SDK 与 WiX 工具链。

| 项目 | MSI | portable | 源码开发 |
| --- | --- | --- | --- |
| 固定 Python/Chromium | 包含 | 不包含 | 由 bootstrap 或开发环境提供 |
| 普通用户推荐 | 是 | 否 | 否 |
| 可自选程序目录 | 是 | 解压目录 | 工作目录 |
| 可写数据目录 | %LocalAppData%\AutoDy | 配置目录下 data | 配置目录下 data |
| Node.js | 不需要 | 普通使用不需要 | 前端构建需要 |

## 2. MSI 首次安装

1. 从正式 Release 下载 AutoDy-1.4.2-x64.msi 及同名 .sha256 文件。最终 Release CI 未通过前，不应把候选产物视为公开发布物。
2. 在下载目录执行 Get-FileHash -Algorithm SHA256 .\AutoDy-1.4.2-x64.msi，并与 sidecar 文件中的值逐字符比较；不一致时停止安装并重新获取可信文件。
3. 双击 MSI，阅读安装向导。新安装在 D: 可用时优先建议 D:\AutoDy；若 D: 不可用，安装器回退到 %LocalAppData%\Programs\AutoDy。也可以在目录页选择其他当前用户可写的目录。
4. 完成后从开始菜单或桌面快捷方式启动。程序数据仍写入 %LocalAppData%\AutoDy，不会跟随自定义程序目录移动。

安装器会记录实际程序目录。修复或升级应复用该目录；登记目录失效或已过期时，安装流程应拒绝使用它，而不是向未知目录写入 payload。

## 3. 首次启动、浏览器资料与登录

首次打开后，管理台会在 127.0.0.1:<selected-port> 提供本机页面。应用使用受管浏览器资料目录，而不是读取用户日常浏览器的个人 profile。请在 AutoDy 管理的浏览器窗口中完成账号登录；不要复制 Cookie、浏览器配置或认证文件到仓库、安装目录或支持工单中。

登录完成后，可在 Dashboard 查看本机状态，在目标、文案和计划页面维护本地工作流，在执行历史中查看运行结果。真实私信操作始终受身份校验、重复保护、确认和浏览器锁控制；文档演示、测试和排障不应进入真实编辑器输入任何内容。

## 4. 端口、托盘与重复启动

首选端口为 8765。若 8765 被无关本地程序监听，AutoDy 不会结束该进程，而是在 8766–8799 内选择第一个安全空闲端口。选择结果可写入本地端口状态，在后续启动时优先复核；因此浏览器地址可能不是 8765。请通过托盘的“打开管理台”入口，而不是猜测端口。

重复启动不会必然生成第二个服务。托盘会核验监听者的服务身份、当前用户和本安装路径；只有确认属于本安装的健康 AutoDy 服务才复用同一 PID。身份不匹配的监听者不被停止或接管。关闭浏览器窗口不会停止托盘；退出托盘也不会删除计划任务或用户数据。“退出并停止 AutoDy”只能停止托盘确认管理的服务。

## 5. 计划、历史与安全重试

用户可查看和维护本地计划。任务运行中使用明确状态表示等待、执行、重试、恢复、完成、最终失败、不确定和取消。只有能够证明发生在发送动作之前的故障才会进入延迟安全重试；成功重试会覆盖为恢复/完成状态。可能发送、确认失败、身份歧义或重复保护无法证明安全时会立即停为不确定，不能人工把它改成自动重试。

历史中的“已解决”表示同一稳定目标存在后续权威成功且之后没有更新失败；它保留审计线索，但不再提供主重试操作。若出现不确定、草稿、附件或身份异常，请保留现场并通过安全渠道排查，不要反复点击重试。

## 6. 修复、升级与卸载

**修复。** 从已安装版本的 Windows 应用管理入口或 MSI 维护模式选择 Repair。修复应恢复程序 payload 和快捷方式，同时不清空 %LocalAppData%\AutoDy 数据目录。

**从 v1.4.1 升级到 v1.4.2。** 使用同一用户运行新版本 MSI。安装器保持 UpgradeCode，检测既有有效安装目录并执行主版本升级。程序目录和快捷方式更新，数据目录保留。升级前后不要手动移动 data 目录；出现目录注册错误时先停止并收集安装日志。

**卸载。** 可从 Windows 应用管理入口或开始菜单中的“卸载 AutoDy”快捷方式执行。卸载删除程序文件和应用快捷方式，默认保留 %LocalAppData%\AutoDy 的用户数据、计划、浏览器资料和备份。只有用户明确确认不再需要这些资料时，才在应用完全退出后处理对应数据目录。

## 7. 常见问题与安全提示

- **页面未打开或地址不确定：** 用托盘“打开管理台”，它会使用当前已验证端口。不要结束所有 Python 进程。
- **显示 AutoDy 已在运行：** 这通常表示发现了可复用服务；若管理台仍打不开，请按维护指南核验服务身份。
- **8765 被占用：** 无关监听者会保持运行；检查 8766–8799 的选择结果，不要强占端口。
- **登录失效：** 在受管浏览器中重新登录。不要导出、上传或共享认证资料。
- **安装失败：** 确认安装目录对当前用户可写、磁盘空间充足，必要时使用 MSI verbose 日志；不要删掉用户数据目录作为第一步。
- **安全边界：** 不使用真实目标、消息或浏览器资料做演示、测试或工单复现。任何无法证明安全的浏览器状态都应停止而非继续。
