# AutoDy 接口设计说明书

## 1. 接口边界

AutoDy 的产品 API 是本机 FastAPI 服务，由 `src/autody/web_api.py` 统一注册，默认只通过 `127.0.0.1:<selected-port>` 提供给本机 Dashboard。API 不设计为公网、多租户或第三方开放平台。

本文件记录资源语义、请求模型、写入 owner 和安全行为。精确 route decorator 与 Pydantic 模型仍是可执行 authority；修改路由时必须同步本文件。

## 2. 通用约定

- 请求/响应以 JSON 为主，文件导入使用 multipart，导出可返回 ZIP/TXT/CSV/JSON/PNG。
- 200：同步成功；202：已启动异步 action；404：资源/接口不存在；409：当前状态、安全或并发冲突；422：输入/业务校验失败。
- 需要真实浏览器的长动作通过 `ActionManager` 启动，返回 job；前端读取 `/api/actions/{job_id}`。
- 409 不等于“可重试”；例如 uncertain、账号/绑定冲突必须按返回语义处理。
- 未知 `/api/{path}` 明确返回 404；只有非 API 路径才进入 SPA 静态资源 fallback。
- API 响应不得包含 Cookie、原始认证资料、browser profile 内容或未脱敏私有运行数据。

## 3. 服务与总览

| Method | Path | 语义 | 主要副作用/约束 |
| --- | --- | --- | --- |
| GET | `/api/service-identity` | 返回 application/version/git commit/Python/package/project/frontend/module 等本机身份 | 只读；托盘仍需结合进程 owner/path 复核 |
| GET | `/api/startup-readiness` | 返回启动 targeted refresh 的准备状态 | 可能读取已启动 action 状态，不发送 |
| GET | `/api/startup-readiness.js` | 提供启动页面可消费的 readiness JS | 只读/no-store |
| GET | `/api/status` | 今日任务、好友状态、历史、Scheduler、issues、statistics | 只读投影；总数使用 executable targets |
| POST | `/api/repair` | 诊断并尝试恢复 runtime/Scheduler/account/binding | 只调用既有 repair owner；不能作为任意系统修复入口 |
| GET | `/api/failed-targets` | 当前安全失败 Target 列表 | 只读；结构化 FailureDetail |
| POST | `/api/failed-targets/{target_id}/retry` | 对一个已证明 safe_retry 的目标补发 | 不满足条件返回 409；uncertain 禁止 |

## 4. 账号接口

| Method | Path | 请求/响应 | 安全语义 |
| --- | --- | --- | --- |
| GET | `/api/account-profile` | 当前公开账号资料 | 不返回原始认证/Cookie |
| POST | `/api/account-profile/refresh` | 启动 `refresh-account-profile` action | 202；使用受管浏览器 |
| GET | `/api/account-profile/avatar` | 当前账号本地头像 | private cache；缺失返回 fallback |
| POST | `/api/account-profile/logout` | `AccountLogoutRequest{confirmed}` | 必须显式确认；写 revalidation guard 后清理受管认证 |
| GET | `/api/account-profiles` | 多账号 registry 的公开投影 | 只读/必要时完成 pending→verified 关联 |
| POST | `/api/account-profiles/{profile_id}/switch` | 切换本地账号 profile | 与发送/dry-run/browser action 互斥；409 fail closed |
| POST | `/api/account-profiles/add` | 创建 pending profile 并启动 login | 202；失败时恢复之前 active profile |

账号切换的 canonical 写入是 `MultiAccountStore`，Web API 不直接搬运账号目录。

## 5. 配置与 Scheduler

### 5.1 配置

`ConfigUpdate` 包含目标显示名列表、retry/timeout/headless、message_suffix/default pack、三类 schedule、recovery deadline、delay/timeouts、friend order/message selection、notification/preflight/log retention 和 scan 参数。

| Method | Path | 行为 |
| --- | --- | --- |
| GET | `/api/config` | 返回当前可公开编辑的 AppConfig 投影 |
| PUT | `/api/config` | 模型校验后原子保存；保留可匹配的既有 Target identity；默认文案包必须存在 |

Target 的 durable binding 字段不通过仅含名字的 ConfigUpdate 被任意重建；好友绑定写入走 Friends API/`binding_recovery`。

### 5.2 Scheduler

| Method | Path | 行为 |
| --- | --- | --- |
| POST | `/api/scheduler/preview` | 比较当前与候选计划，不写 Windows Tasks |
| POST | `/api/scheduler/apply` | 保存候选并通过 SchedulerService 应用 Windows Tasks |
| POST | `/api/scheduler/{operation}` | `install/update/repair` 走 repair；`remove` 走 remove；其他 404 |

Windows 写操作最终落到受约束 PowerShell/UAC owner；API 不在 Python 中维护第二套 task definition。

## 6. 历史、文案与文案包

### 6.1 历史

`GET /api/history` 支持 `start_date/end_date/status_filter/task_type/page/page_size`，由 `TaskHistoryStore` 从 `history/task-runs.jsonl` 分页查询。

### 6.2 本地文案

| Method | Path | 行为 |
| --- | --- | --- |
| GET | `/api/messages` | 读取本地去空行文案 |
| PUT | `/api/messages` | 去重、拒绝空库、临时文件后 replace |
| POST | `/api/messages/import/preview` | 解析上传 TXT/CSV/JSON，返回总数/有效/重复/空/过长/链接统计 |
| POST | `/api/messages/import` | merge/replace 导入 |
| POST | `/api/messages/deduplicate` | 使用同一 parser/import owner 原位去重 |
| GET | `/api/messages/export` | `format=txt|csv|json`；可从 local 或 pack/category 导出 |

### 6.3 文案包

| Method | Path | 行为 |
| --- | --- | --- |
| GET/POST | `/api/message-packs` | 列表 / 创建自定义包 |
| POST | `/api/message-packs/import` | 从本地 TXT 创建/导入包 |
| PUT | `/api/message-packs/order` | revision-aware 排序 |
| GET/PATCH/DELETE | `/api/message-packs/{pack_id}` | 预览 / 重命名 / 删除 |
| POST | `/api/message-packs/{pack_id}/messages` | 新增消息 |
| PATCH/DELETE | `/api/message-packs/{pack_id}/messages/{message_id}` | 修改/删除消息 |
| POST | `/api/message-packs/{source_id}/fuse` | 合并到目标包 |
| POST | `/api/message-packs/{destination_id}/split` | 从来源拆分 |
| POST | `/api/message-packs/{pack_id}/import` | 把包内容 merge/replace 到本地文案库 |

写接口使用 `expected_revision` 防止前端基于陈旧视图覆盖 catalog。

## 7. 好友与绑定接口

| Method | Path | 行为/安全条件 |
| --- | --- | --- |
| POST | `/api/friends/scan` | 启动好友扫描 action |
| POST | `/api/friends/discover` | 强制一次只读完整扫描，即使缓存仍新鲜 |
| GET | `/api/friends/discovered` | 返回扫描时间、stale/refresh、candidate、orphan 和 reassociation 状态 |
| GET | `/api/friends/scan-status` | 返回扫描阶段/progress/last_result |
| GET | `/api/friends` | 返回 configured Target 的当前 binding/today/avatar 投影 |
| POST | `/api/friends/discovered/batch` | 批量加入满足权威 identity/account/current/未占用条件的 candidate |
| POST | `/api/friends/{candidate_id}/relink` | `FriendRelinkRequest{target_id}`；调用 `reassociate_stable_binding` |
| POST | `/api/friends/{target_id}/ignore-orphan` | 本地忽略一个 orphan 提示，不删除 Target |
| POST | `/api/friends/{candidate_id}/add-to-targets` | 单 candidate 加入；弱身份/歧义/needs_reassociation 拒绝 |
| POST | `/api/friends/refresh-avatars` | 启动只读头像刷新 action |
| PATCH | `/api/friends/batch` | `enable/disable/delete`；保存后重新计算 binding guard |
| GET | `/api/avatars/{friend_id}` | 返回本地 PNG 或 fallback SVG |

好友写入必须由 stable Target/binding owner 完成；API 不接受“名字相同所以重新绑定”的快捷路径。

## 8. 日志与诊断接口

| Method | Path | 行为 |
| --- | --- | --- |
| GET | `/api/logs` | 按日期/级别/任务类型/状态分页返回脱敏日志 + scheduler tail |
| GET | `/api/logs/storage-summary` | 文件/容量与保留配置摘要 |
| POST | `/api/logs/cleanup-preview` | 只计算将整理的日志 |
| POST | `/api/logs/cleanup` | 必须 `confirmed=true` 才应用保留策略 |
| POST | `/api/logs/archive` | 把指定日期前日志移入 archive |
| POST | `/api/logs/archive-historical` | 按现有策略归档历史日志 |
| GET | `/api/logs/diagnostic-export` | ZIP：manifest + recent masked summary；显式排除消息/Cookie/profile/avatar/discovery |
| POST | `/api/logs/open-folder` | Windows 本机打开日志目录 |

日志清理只作用于明确 log root，不是 DataRoot 通用删除接口。

## 9. 备份接口

| Method | Path | 行为 |
| --- | --- | --- |
| GET | `/api/backup` | legacy v1 本地备份兼容入口 |
| POST | `/api/backup/export` | `BackupExportRequest{categories}` 生成 checksummed v2 package |
| POST | `/api/backup/preview` | 验证上传备份并返回变化预览 |
| POST | `/api/backup/import` | merge/replace 导入；兼容安全的 legacy v1 |

新导出使用类别/manifest/checksum，不包含 browser profile。legacy import 写入前创建当前备份，config/messages 写入异常时恢复原值。

## 10. Preflight 接口

| Method | Path | 行为 |
| --- | --- | --- |
| GET | `/api/preflight/latest` | 最新只读检查结果 |
| GET | `/api/preflight/history` | 最近历史（API 投影最多取后 30 条） |
| GET | `/api/preflight/status` | action/job/progress/latest 聚合 |
| POST | `/api/preflight/run` | `PreflightRunRequest{target_ids?}`；目标必须属于当前 executable set；202 |
| POST | `/api/preflight/cancel` | 写 cancel request；不通过杀浏览器取消 |

Preflight 本身不选择消息、不调用 sender、不输入编辑器。

## 11. 通用异步 Action

| Method | Path | 行为 |
| --- | --- | --- |
| POST | `/api/actions/{action}` | 允许 `run/login/health-check/scan-friends/refresh-friend-avatars/repair-playwright/refresh-account-profile/preflight`；其他 404 |
| GET | `/api/actions/{job_id}` | 返回 action 状态；不存在 404 |

同类浏览器 action 已运行时返回 409，前端应等待当前 job 而不是重复启动。

## 12. Test Center 模块接口

可选模块统一位于 `/api/modules/autody-test-center/*`：

- `/api/modules`：核心模块状态、bundled version/package/update 状态；
- `install` / `uninstall`：安装或移除官方模块，运行中的 dry-run 阻止替换；
- `today-plan`、`failed-targets`、目标级 retry：复用核心 helper；
- `diagnostics`、`history`、`preview`/`preview/select`；
- `dry-run/status`、`message-preview`、`settings`、`select`、`start`、`pause`、`resume`、`stop`、`focus-browser`、`history`；
- `fixtures`、`simulate-failure`：只生成安全夹具/受控失败，不调用真实发送；
- `preflight/status`、`preflight/run`、`preflight/cancel`；
- `frontend/{path}`：只从模块 frontend root 安全返回静态文件；
- `targets/{target_id}/settings`：模块目标覆盖，数据写模块 `overrides.json`。

模块 API 不能放宽核心账号、binding、browser lock 或 sender safety。

## 13. 接口变更规则

1. 增删路由同步本文件与前端调用；结构变化同步 07 数据字典。
2. 任何会触发浏览器/文件/Task Scheduler 的接口都必须明确 owner 和失败状态。
3. 新增“自动重试”类接口必须证明 safe-before-send，不得用 HTTP 200/409 简化发送语义。
4. API 永远不能成为导出 Cookie/profile/真实消息的调试后门。
5. 路由级测试主要集中在 `tests/test_web_api.py`；领域规则同时要在对应 owner 的测试中存在，避免只靠 HTTP 测试固化业务逻辑。
