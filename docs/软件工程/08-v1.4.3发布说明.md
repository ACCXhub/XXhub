# AutoDy v1.4.3 发布说明

> 已验证稳定源码基线，尚未创建 v1.4.3 标签或 GitHub Release。本地 MSI 仅用于冻结验证，不是公开发布资产。

## 概览

v1.4.3 完成最后一轮产品清理：历史日级统计不再受今天配置影响，Dashboard 与好友页去除重复或危险入口，文案包只使用内置内容；同时让提升后的 MSI 始终使用原交互用户的 SID、LocalAppData 和计划任务 Principal。

## 产品状态与界面修复

Dashboard 的 7 天/30 天成功率和连续成功天数使用每个历史日期自己的 daily facts 与运行结果。今天启用或停用目标不会改写过去的成功日；缺失日不进入成功率分母，但会中断连续成功。Dashboard 移除逐次运行表、阶段标签和重试次数，详细历史统一在日志页查看。只有存在明确安全可重试的当日失败目标时才显示“补发”。

好友管理保留整行一键加入或取消续火、重新关联和忽略缓存，移除每一行的垃圾桶，删除只通过页头“全部删除”明确执行。文案包页只列出随 AutoDy 安装的五个内置示例包；设置、API、备份和运行时不再暴露远程索引 URL 或远程回退状态。

同一稳定账号重新登录时继续关联既有目标、计划、历史、模块设置和账号元数据；不同账号仍保持本地状态隔离。稳定身份来自验证后的本地账号 profile 标识，不使用显示名、进程或临时浏览器会话作为账号键。

## 安装与升级变化

新安装仍优先使用 D:\AutoDy；D: 不可用时回退到原交互用户的 %LocalAppData%\Programs\AutoDy。MSI 使用 per-machine 提升语义，但在提升前捕获原交互用户 SID 与 LocalAppData，并明确把 config.yaml、注册信息和计划任务绑定给该用户。安装、Repair 或升级不得从提升管理员进程的 %LOCALAPPDATA% 推断 DataRoot。首次配置使用 NeverOverwrite，卸载默认保留计划、历史、受管资料和备份。

Scheduler 修复命令显式接收 config、ProgramRoot、DataRoot 与目标用户 SID。安装脚本用 Limited Principal 注册任务，完成后重新读取并校验脚本、根目录、工作目录、时间、重复窗口和 SID；任何漂移都会让安装/Repair 明确失败。1.4.3 本地 MSI 已执行 BuildOnly 冻结验证，但没有上传或发布。

## 启动、端口与服务身份

默认端口仍为 8765。若该端口由无关监听者占用，AutoDy 在 8766–8799 中选择安全空闲端口，并可持久化选择以供下次启动复核。无关监听者保持存活。重复启动时，托盘通过服务身份、当前用户、安装/包路径和 Python 解释器验证服务；验证通过才复用同一端口和 PID，验证失败不附着也不停止。

## 构建、完整性与隐私

MSI、portable 和模块包使用受控输入，MSI 已有字节级确定性构建验证。D3DCompiler_47.dll 已验证随预期 payload 提供。发布产物使用 SHA-256、manifest、allowlist 和隐私扫描；发布检查失败时保留受控诊断，以便定位规则或输入问题，不包含运行时私密数据。

下载安装候选或正式包后，使用 Get-FileHash -Algorithm SHA256 比较同名 .sha256 文件。哈希不一致时不要安装。MSI 当前未声明代码签名，Windows 或企业策略提示应通过可信来源、哈希和组织规范处理，而不是关闭安全软件、使用 UPX 或下载来源不明的 DLL。

## 已知限制与选择

普通用户应选择正式 Release 中的 MSI；portable 需要 Python 3.11 和网络，源码用于开发。产品仅提供本机服务，浏览器行为仍受登录状态和页面变化影响。真实账号、消息和浏览器资料不属于支持、测试或文档输入。当前没有 v1.4.3 正式资产，不应把本地构建当作公开版本。

## 获取与反馈前的确认

选择安装方式前，普通用户应确认需要的是包含固定运行时的 MSI，而不是源码归档；需要便携部署且能够维护 Python 环境的用户才选择 portable。安装前核对 SHA-256，安装后从托盘打开本机 Dashboard。若端口不是 8765，这通常是安全回退而不是故障；不要为了恢复固定端口结束无关监听者。

如遇安装、登录、端口或升级问题，请按中文运维手册收集最小必要错误摘要。不要提交真实账号、目标、消息、Cookie、浏览器 profile、备份或完整运行时日志。候选期间的反馈用于完善最终 CI 前的交付质量，不构成已发布版本的服务承诺。

候选状态改变为正式发布前，发布负责人仍需核对 CI、标签、正式资产和 checksum sidecar 的一致性。若其中任一项不一致，应继续保持候选状态并重新生成或验证，不应以文档中的功能清单推定发布已完成。

正式发布后，本文才可补充实际发布日期与 Release 链接；在此之前保留候选标识是为了避免用户把本地构建或预览文件误认为稳定交付物。
