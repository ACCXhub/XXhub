# AutoDy v1.4.2 发布说明

> 发布候选，等待最终 CI 通过。本文没有发布日期，也不代表 v1.4.2 已发布。

## 概览

v1.4.2 聚焦产品状态一致性、Windows 本机安装、服务启动和发行物可审计性。候选版本统一 Dashboard、今日计划和调度器的目标口径，恢复好友管理与异常详情的紧凑交互；同时强化 MSI 目录选择、本机服务身份、端口冲突处理，以及构建输入、哈希、manifest 和隐私诊断。

## 产品状态与界面修复

Dashboard 与今日计划使用同一当前可执行目标集合，并按目标采用当天最新结构化结果；后续成功可以解决当前失败状态，但不会删除历史失败。Overview 每次运行只显示一条紧凑父行，异常详情默认折叠并按原因分组，页面只保留一个“重试所有目标”入口。

好友管理恢复整行一键加入或取消续火，后端确认后立即更新界面；取消的目标无需删除记录或手动刷新即可重新加入。页头提供全量启用、停用和删除，删除仍为独立确认操作。定时任务页显示配置时间、Windows 状态、当前目标数、上次结果和漂移状态，目标数与 Dashboard 来自同一权威集合。

同一稳定账号重新登录时继续关联既有目标、计划、历史、模块设置和账号元数据；不同账号仍保持本地状态隔离。稳定身份来自验证后的本地账号 profile 标识，不使用显示名、进程或临时浏览器会话作为账号键。

## 安装与升级变化

新安装优先使用 D:\AutoDy；D: 不可用时回退到 %LocalAppData%\Programs\AutoDy，并可在向导中选择其他可写目录。安装器会登记实际程序目录，Repair 与升级复用有效位置并拒绝陈旧路径。开始菜单提供卸载快捷方式。程序目录与 %LocalAppData%\AutoDy 用户数据分离，卸载默认保留计划、历史、受管资料和备份。

从 v1.4.1 升级到 v1.4.2 时，请在同一用户下运行新 MSI，不要手动移动程序或数据目录。已完成的生命周期验证覆盖 Upgrade、Repair、卸载快捷方式和数据保留；最终发布仍需通过本次候选提交的 Release CI。

## 启动、端口与服务身份

默认端口仍为 8765。若该端口由无关监听者占用，AutoDy 在 8766–8799 中选择安全空闲端口，并可持久化选择以供下次启动复核。无关监听者保持存活。重复启动时，托盘通过服务身份、当前用户、安装/包路径和 Python 解释器验证服务；验证通过才复用同一端口和 PID，验证失败不附着也不停止。

## 构建、完整性与隐私

MSI、portable 和模块包使用受控输入，MSI 已有字节级确定性构建验证。D3DCompiler_47.dll 已验证随预期 payload 提供。发布产物使用 SHA-256、manifest、allowlist 和隐私扫描；发布检查失败时保留受控诊断，以便定位规则或输入问题，不包含运行时私密数据。

下载安装候选或正式包后，使用 Get-FileHash -Algorithm SHA256 比较同名 .sha256 文件。哈希不一致时不要安装。MSI 当前未声明代码签名，Windows 或企业策略提示应通过可信来源、哈希和组织规范处理，而不是关闭安全软件、使用 UPX 或下载来源不明的 DLL。

## 已知限制与选择

普通用户应选择 MSI；portable 需要 Python 3.11 和网络，源码用于开发。产品仅提供本机服务，浏览器行为仍受登录状态和页面变化影响。真实账号、消息和浏览器资料不属于支持、测试或文档输入。v1.4.2 的最终发布状态取决于最终 CI；通过前请勿将候选包视为正式版本。

## 获取与反馈前的确认

选择安装方式前，普通用户应确认需要的是包含固定运行时的 MSI，而不是源码归档；需要便携部署且能够维护 Python 环境的用户才选择 portable。安装前核对 SHA-256，安装后从托盘打开本机 Dashboard。若端口不是 8765，这通常是安全回退而不是故障；不要为了恢复固定端口结束无关监听者。

如遇安装、登录、端口或升级问题，请按中文运维手册收集最小必要错误摘要。不要提交真实账号、目标、消息、Cookie、浏览器 profile、备份或完整运行时日志。候选期间的反馈用于完善最终 CI 前的交付质量，不构成已发布版本的服务承诺。

候选状态改变为正式发布前，发布负责人仍需核对 CI、标签、正式资产和 checksum sidecar 的一致性。若其中任一项不一致，应继续保持候选状态并重新生成或验证，不应以文档中的功能清单推定发布已完成。

正式发布后，本文才可补充实际发布日期与 Release 链接；在此之前保留候选标识是为了避免用户把本地构建或预览文件误认为稳定交付物。
