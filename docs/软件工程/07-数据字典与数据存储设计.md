# AutoDy 数据字典与数据存储设计

## 1. 总体说明

AutoDy 当前不使用关系数据库。本数据字典记录实际存在的 YAML、JSON、JSONL、TXT、PNG、浏览器 profile、Windows Registry 和 Task Scheduler 状态。任何未来数据结构变更都应更新对应 owner 与本文件，而不是虚构 SQL 表或把整个 DataRoot 当成一个无结构目录。

### 1.1 存储根

- **Source**：配置文件所在项目根/显式 DataRoot。
- **MSI installed**：ProgramRoot 与 DataRoot 分离；DataRoot 为原交互用户 `%LocalAppData%\AutoDy`。
- **Portable**：ProgramRoot/DataRoot 均在解包根，由共享 resolver 解释。

本文中的 `data/...` 均指当前 DataRoot 下的运行数据区域；真实路径不应写入公共文档/诊断。

### 1.2 敏感级别

| 级别 | 含义 | 示例 |
| --- | --- | --- |
| Public/Program | 可公开程序事实 | 版本、模块版本、发布 manifest |
| Local | 本机运行状态，可脱敏诊断 | selected port、匿名 run_id、阶段/错误码 |
| Private | 用户业务/身份资料 | Target、好友缓存、账号显示信息、消息、历史 |
| Auth-sensitive | 认证/会话凭据 | browser profile、Cookie、local storage |

Private/Auth-sensitive 不进入 Git、Release 或普通诊断。

## 2. `config.yaml`

Owner：`src/autody/config.py`。写入方式：临时文件 + flush/fsync + `os.replace`。相对路径以 `config.yaml` 所在目录解析。

### 2.1 `Target`

| 字段 | 类型 | 默认/约束 | 语义 | 敏感级别 |
| --- | --- | --- | --- | --- |
| `name` | string | 必填，非空 | 用户可见名称；仅展示/legacy 兼容，不是 durable identity | Private |
| `enabled` | bool | `true` | 是否参与当前续火集合 | Private |
| `note` | string | `""` | 本地备注 | Private |
| `stable_id` | string? | 唯一 | AutoDy 内部持久 Target ID | Private |
| `candidate_id` | string? | 唯一 | 当前 discovery/candidate 关联键；不是永久好友身份证明 | Private |
| `binding_identity_key` | string? | 与 source/scope 组合使用 | 权威 durable friend proof | Private |
| `binding_identity_source` | string? | 必须来自 binding allowlist 才能自动/显式证明 | identity key 来源 | Private |
| `binding_account_scope` | string? | 当前账号兼容才有效 | durable proof 所属账号范围 | Private |
| `message_pack` | string? | 必须引用存在的 pack ID | Target 显式文案包 | Private |
| `suffix_override` | string? | 最长由 API 限制 | 自定义后缀文本 | Private |
| `suffix_mode` | enum | `global`; `global/disabled/custom` | 后缀继承方式 | Local/Private |
| `delay_offset_minutes` | int | `0`, 0–30 | 相对每日主计划的目标延迟 | Local |
| `message_selection` | enum? | `one_for_all/per_friend` | Target 级覆盖 | Local |
| `send_order` | int? | >=0 | 目标顺序覆盖 | Local |

身份规则：`stable_id` 是 AutoDy 主键；`binding_*` 才是好友 durable proof；`candidate_id`/conversation locator 只表示当前 discovery 导航。显示名与头像不参与权威 join。

## 3. 文案与文案包

### 3.1 `messages.txt`

Owner：`messages.py` / `transfer.py` / Web API adapter。格式：UTF-8，一行一条非空消息。导入支持 TXT/CSV/JSON；写入去空、去重，拒绝空库。内容是 Private，不写日志、文档或发布包中的用户运行数据。

### 3.2 message pack catalog

Owner：`MessagePackService` 与 message pack catalog。稳定引用键是 pack `id`，`default_message_pack` 与 Target `message_pack` 只保存 ID，不复制包内容到 config。写操作使用 revision 防止陈旧覆盖。内置 pack 属于 ProgramRoot 受控资源；自定义 pack 属于本地可编辑数据边界。

## 4. `data/state.json`

Owner：`src/autody/state.py`。

```text
AppState
├─ rotation
│  ├─ order: list[string]
│  └─ consumed: list[string]
└─ daily: map[YYYY-MM-DD, object]
```

`rotation.order/consumed` 管理文案轮换。`daily` 是按日期兼容状态，当前代码会保存/读取例如 message、succeeded、failures、confirmation_results、consumed、task_run_id、target_failures 等运行字段；这些字段应与 Runner/History 投影协作，不能单独作为跨版本数据库 schema 使用。

写入为临时 JSON + `os.replace`。文件损坏会抛出明确 ValueError，而不是静默重置。

## 5. 任务历史与重试

### 5.1 `data/history/task-runs.jsonl`

Owner：`TaskHistoryStore`。

`TaskRunRecord`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` | string | 一次任务运行 ID |
| `date` | string | 业务日期 |
| `task_type` | enum | `daily_send/health_check/login/friend_scan/system` |
| `trigger_source` | enum | `scheduled/manual/startup_recovery/retry` |
| `start_time/end_time` | string | ISO 时间 |
| `duration` | float | 秒 |
| `total_targets/success_count/failed_count/skipped_count/retry_count` | int | 汇总计数 |
| `final_status` | string | 运行终态 |
| `base_message_id` | string? | 文案摘要 ID，不等于消息正文 |
| `message_pack` | string? | pack 标识 |
| `error_summary` | string? | 受控错误摘要 |
| `failed_target_ids` | list[string] | stable Target IDs |
| `confirmation_results` | map | Target→确认结果 |
| `target_failures` | map | Target→`FailureDetail` |

文件 append-only；损坏行读取时计入 `invalid_count`，不删除其他历史。

### 5.2 `data/history/task-outcomes.json`

Owner：`retry_state.py` / Runner。以 run_id 保存 retry_pending/final_failed/uncertain/cancelled/recovery 等调度事实、next attempt 与 retry attempts。它决定自动恢复是否仍允许，不由 UI 直接改写。

## 6. `FailureDetail`

Owner：`failures.py`。实际字段以 Pydantic 模型为准；跨模块至少表达 reason code、失败 stage、run/target/account/binding 证据、send attempts、是否 uncertain、是否 safe retry 和给用户的摘要/建议动作。

关键语义：`safe_retry_available=true` 只能来自发送动作前已证明失败；`uncertain_send=true` 禁止自动重试。历史 FailureDetail 不能因 binding 后来恢复被删除。

## 7. 好友 discovery

### 7.1 `data/discovered_friends.json`

Owner：`friend_discovery.py`。

`FriendDiscoveryResult` 主要字段：`scanned_at`、`scan_id`、`last_result`、`account_scope`、`target_refresh`、`candidates[]`。

`FriendCandidate`：

| 字段 | 语义 |
| --- | --- |
| `candidate_id` | 本地当前候选键；可关联 Target，但不是 durable friend identity |
| `display_name` | 当前页面显示名 |
| `identity_key/source` | 当前扫描中的权威身份材料 |
| `conversation_id` | 当前会话 locator |
| `presence_status` | current/stale 等当前性 |
| `match_status` | configured/ambiguous/needs_reassociation 等 UI/绑定状态 |
| `configured_target_id/enabled` | 当前缓存反向展示信息 |
| `avatar_cache_key/path/status/updated_at` | 头像缓存引用 |
| `discovered_at/first_discovered_at/last_seen_at/last_scan_id` | discovery 时间证据 |

完整 cache 默认 24h TTL。失败/不完整扫描不应把旧有效 binding 自动降级成名称猜测。

### 7.2 `data/friend_scan_progress.json`

短生命周期进度：`running/stage/message/current/total/timings`，结束时可带 `status/total_seconds/...details`。用于 UI polling，不是 binding authority。

### 7.3 `data/avatar-cache/*.png`

Private 本地缓存，默认 7 天 TTL。头像只用于展示；不得作为 durable identity proof。诊断/备份默认排除。

### 7.4 `data/ignored-friend-bindings.json`

结构：`{"target_ids": [stable_id...]}`。只表示用户忽略 orphan/reassociation 提示，不删除 Target 或修改 durable proof。

## 8. 账号数据

### 8.1 `data/account-profile.json`

Owner：`account_profile.py`。`AccountProfile` 字段：

`account_profile_id`、`account_id_digest`、`display_name`、`avatar_cache_key`、`avatar_version`、`is_self`、`verification_source`、`profile_status`、`verified_at`、`last_updated_at`、`switched`。

原始平台账号认证不写入该公开元数据文件；API 返回受控 public profile。

### 8.2 `data/account-avatar/profile.png`

Private 本地头像，仅用于 Dashboard；不进入普通诊断。

### 8.3 `data/account-binding-state.json`

结构核心：`status=revalidation_required`、`updated_at`。退出/认证清理前先写 guard；只有 canonical binding proof 全部重新成立后删除该文件。

### 8.4 `data/account-profiles/registry.json`

Owner：`MultiAccountStore`，`format_version=1`。核心字段：

- `active_profile_id`
- `profiles{profile_id -> profile_id/display_name/profile_status/logged_in/created_at/last_active_at/...}`
- `migration{status/completed_at/rollback_manifest}`

profile ID 仅允许 `account-<24 hex>` 或 `pending-<24 hex>`。

### 8.5 每账号目录

`data/account-profiles/<profile_id>/` 包含：

- `account-settings.json`：format_version、targets 和账号级 schedule 字段；
- `browser-profile/`：Auth-sensitive Chromium profile；
- `account-profile.json`、`account-avatar/`；
- `runtime/` 下 snapshot：state/discovery/ignored binding/health/scan progress/binding guard、avatar-cache、history、notifications、Test Center data。

激活账号时这些 snapshot 投影回 DataRoot compatibility working set。

### 8.6 migration backups

`data/account-profile-migration-backups/<timestamp>/` 保存迁移前 `config.yaml`、browser backup 和 `rollback-manifest.json`。这是迁移恢复证据，不进入 Release/普通诊断。

## 9. Preflight 数据

Owner：`PreflightStore`。

- `data/preflight/latest.json`：最近完整结果；
- `data/preflight/history.jsonl`：最多保留后 90 条且约 90 天窗口；
- `data/preflight/progress.json`：`running/completed_targets/total_targets/current_status`；
- `data/preflight/request.json`：本次目标 ID 请求；
- `data/preflight/cancel.json`：取消请求时间。

结果包含 Target readiness 证据和 read-only action counts。消息写动作计数应保持 0。

## 10. 日志与通知

### 10.1 `data/logs/`

Owner：`log_center.py`/logging setup。日志按日期/类型存放，`archive/` 保存归档。配置控制 active/archive retention 和 friend-name masking。普通诊断只导出受控摘要。

### 10.2 `data/notifications/need-attention.txt`

本地提醒兼容状态；当前 Dashboard 优先从结构化 FailureDetail 生成需处理项，陈旧通知不得覆盖当前已解决事实。

## 11. 备份

新备份 owner：`transfer.py`。v2 ZIP 采用 manifest/checksum/类别选择；Web API 仍兼容 legacy v1（`config.yaml`、`messages.txt`、可选 state、manifest）。

备份前/导入前的恢复副本位于 `data/backups/`。普通备份不包含 browser profile/Cookie；导入必须 preview/validate，写入失败恢复原配置和文案。

## 12. Test Center 数据

`data/modules/autody-test-center/data/` 是可选模块的数据 owner。已存在：

- `overrides.json`：Target 级 message pack/suffix/delay/order 等模块覆盖；
- `history.jsonl`：模块操作摘要；
- `preview/state.json`：预览选中 Target；
- `preflight/`：模块只读 preflight request/cancel/history；
- `fixtures/safe-fixture.json`：文档/测试安全夹具；
- dry-run controller 自有设置/历史/恢复状态。

卸载模块时此模块 data 会按确认语义删除，但核心 Target、messages、history、browser data 不应受影响。

## 13. 浏览器资料

`profile_dir` 或账号 `browser-profile/` 是 Auth-sensitive。可包含 Cookie、local storage、IndexedDB、cache/service worker 等登录材料。它只供 AutoDy 受管 Chromium 使用：

- 不通过 API 导出；
- 不进入 Git/Release/普通 backup/diagnostic；
- 退出账号时只清理 Douyin 管理 origin/cookies，并先启用 binding revalidation guard；
- 普通 MSI 卸载默认保留 DataRoot，因此 browser profile 也默认保留，除非用户执行明确的数据删除。

## 14. 锁、服务和运行提示

- `data/locks/autody.lock`：真实任务 SingleInstanceLock owner；并发任务失败而非破锁。
- `daily-send-active.json` 等发送 marker：账号切换 guard 使用的运行态证据。
- `health.json`：本机健康状态；不存在时 API 可从受控日志回退推断。
- service-port hint（由托盘维护）：只是候选端口提示，每次启动必须重新验证 service identity，不是信任凭据。
- watchdog 恢复状态/计数：属于托盘本机状态，记录自动尝试和手动停止 suppression；不含消息内容。

## 15. Windows Registry

MSI 维护原交互用户/安装信息，核心语义至少包括：

- `InstallFolder`：实际 ProgramRoot；
- `DataRoot`：原交互用户数据根；
- `InstalledVersion`：安装版本。

安装器/生命周期验证还固定 UpgradeCode、ProductCode/PackageCode 和相关安全属性。Registry 值是维护线索，使用前仍需验证对应目录/payload；陈旧值不能被当作安全写入许可。

## 16. Windows Task Scheduler

三个 canonical task 名：

- `AutoDy-Health-Daily`
- `AutoDy-DailySpark`
- `AutoDy-Health-Weekly`

每项持久事实包括启用/存在状态、trigger、脚本/参数、ProgramRoot、DataRoot、WorkingDirectory、Principal、RunLevel、重复窗口等。任务使用原交互用户 Principal、`RunLevel Limited`。Scheduler 快照读取失败不等于 0 项任务。

## 17. Release 数据

`output/release/v<version>/` 是构建生成的 canonical candidate 目录，不进入 Git。正式可能包含：

- `AutoDy-<version>-x64.msi`
- `.msi.sha256`
- `AutoDy-Windows-Portable-<version>.zip`
- `.zip.sha256`
- `release-manifest.json`
- privacy/lifecycle reports（按流程保留/诊断）

`output/work/` 只用于可再生成 staging/diagnostics；成功后应收敛临时目录，失败时可保留当前诊断现场。版本历史由 Git/Release 保存，不依赖堆积 work staging。

## 18. 数据生命周期矩阵

| 数据 | 创建/更新 | 普通卸载 | Backup | Release | 清理 owner |
| --- | --- | --- | --- | --- | --- |
| ProgramRoot | MSI/Portable | MSI 删除 | 否 | 是程序 payload | MSI/用户删除 portable |
| config/messages | 用户/API | 保留 | 是（选择类别） | 不含用户值 | 用户明确操作 |
| state/history | Runner | 保留 | 可选 | 否 | 产品保留/用户决定 |
| browser profile/Cookie | 受管浏览器 | 保留 | 否 | 否 | 账号 logout/明确数据删除 |
| discovery/avatar | 扫描 | 保留 | 默认否 | 否 | discovery/cache owner |
| logs | runtime | 保留 | 默认否 | 否 | log retention |
| account profile/snapshots | account owner | 保留 | 受策略控制 | 否 | account owner |
| preflight/Test Center | 对应模块 | 保留 | 依类别 | 否 | store/module |
| Registry/Tasks | MSI/Scheduler | 删除 | 否 | 不适用 | MSI/Scheduler |
| output/work | build/release | 不适用 | 否 | 否 | build scripts |

## 19. 数据变更规则

新增持久字段时必须回答：owner、默认值、向后兼容、原子写入、敏感级别、备份策略、卸载/账号切换/迁移行为和测试。任何把“显示名/locator/缓存”升级为 durable identity 的变更都属于安全 schema 变更，必须更新 03/05/08/12。
