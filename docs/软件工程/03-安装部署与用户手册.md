# AutoDy 安装部署与用户手册

## 1. 使用前说明

本手册适用于 AutoDy 1.4.3 已验证稳定源码基线。当前尚无 v1.4.3 标签或 GitHub Release，本地 MSI 仅用于冻结验证，不是公开发布资产。普通用户优先使用正式 Release 的 MSI；portable 适合需要解压即用、并接受数据随目录保存的技术用户；源码包只用于开发。无论使用哪一种方式，都不应把真实账号资料、Cookie、浏览器 profile 或消息内容提供给他人排障。

## 2. 环境与下载校验

支持 Windows x64。MSI 与 portable 都包含固定 Python、Python/native 依赖、Chromium、生产前端、文案包和官方模块；运行时不需要系统 Python、Node/npm、仓库或联网恢复依赖。下载完成后，在下载目录执行：

~~~powershell
Get-FileHash -Algorithm SHA256 '.\AutoDy-1.4.3-x64.msi'
~~~

将结果与同名 .sha256 文件逐字符对比。预期结果是完全一致；若不一致，不要安装、不要反复双击候选包，应删除该下载文件并从可信正式渠道重新获取。

## 3. 首次 MSI 安装

步骤一：双击 MSI 并同意 Windows 提升提示；安装器会在提升前捕获原交互用户身份，不能把管理员账户的数据目录用于 AutoDy。步骤二：在安装目录页查看默认建议。新安装时若 D: 可用，安装器优先 D:\AutoDy；D: 不可用时回退到原交互用户的 %LocalAppData%\Programs\AutoDy。步骤三：如有组织目录规范，可选择其他明确的空目录；不要选择网络共享、浏览器目录或其他应用目录。步骤四：完成向导后，从开始菜单或桌面快捷方式打开 AutoDy。

预期结果是程序文件位于选择的程序目录，用户数据位于 %LocalAppData%\AutoDy，二者不混合。若目录页拒绝已有路径、提示陈旧安装位置或安装失败，停止继续安装，检查目录是否被手动删除、是否可写及是否存在旧安装记录；不要先删除 %LocalAppData%\AutoDy。

## 4. 首次启动、Dashboard 与受管浏览器

从快捷方式或通知区域托盘选择“打开 AutoDy 管理台”。管理台使用 127.0.0.1:<selected-port>；通常端口为 8765。首次服务启动后，Dashboard 显示本机状态、计划、历史和设置。若页面没有出现，等待托盘状态稳定后再次选择打开入口；仍失败时转到故障排查手册的“Dashboard 不打开”。

账号登录应仅在 AutoDy 启动的受管 Chromium 中完成。该 profile 与日常浏览器 profile 隔离，不能通过复制 Cookie 或浏览器目录代替登录。预期结果是 Dashboard 显示本机可用状态；若登录过期，在同一受管窗口重新登录。发现草稿、附件、身份不一致或任何不确定页面状态时，应停止而不是尝试输入或发送。

## 5. 托盘、重复启动与端口

关闭浏览器窗口不停止托盘；计划任务也可以独立运行。重复点击快捷方式时，托盘先验证已有监听者是否属于当前 AutoDy，再复用同一服务和 PID。若提示已在运行且页面可打开，这是预期复用，不必结束进程。

8765 被无关服务占用时，AutoDy 不结束对方，而在 8766–8799 内寻找空闲端口。选中端口可以持久化，下一次启动会优先复核，因此地址不一定永远是 8765。预期结果是托盘打开正确页面；若仍连接旧地址，请用托盘入口而不是猜测端口。所有候选端口不可用时，系统应报错，用户不得通过批量结束 Python、PowerShell、Chrome 或 Edge 来“腾出端口”。

## 6. 日常使用与状态理解

Dashboard 用于查看本地概览和历史；目标、文案与计划页面用于维护本地工作流。运行状态中的 retry_pending 表示系统已经证明失败发生在可能发送之前，并安排受完成窗口约束的重试；recovered 表示随后重试成功；final_failed 表示安全重试耗尽；uncertain 表示可能发送、身份或确认不确定，绝不自动重试。已解决的历史失败表示同一稳定目标已有后续权威成功且之后无更新失败，保留记录但不再提供主重试入口。

Dashboard 日常以普通用户权限运行。只有用户在“定时任务”页明确选择安装、修复、移除或“应用到 Windows 任务”时，Windows 才会为该次操作显示 UAC；同意后一次性管理员子进程完成操作并立即退出，Dashboard 和计划任务本身不会变成管理员进程。取消 UAC 时任务与计划设置保持不变，页面会返回取消结果；不要因为提示暂时不可见而连续点击。

用户不应通过刷新、关闭浏览器或重复点击来改变安全状态。任何不确定结果都应保留现场、查看历史和诊断，并在需要时由维护人员按安全手册检查。

## 7. Portable 使用

将 `AutoDy-Windows-Portable-1.4.3.zip` 完整解压到一个独立、可写且路径稳定的目录，然后双击顶层 `AutoDy.cmd`。不要从 ZIP 内直接运行，也不要只复制启动脚本。程序、嵌入 Python、Chromium、配置、历史和浏览器资料都位于该解包目录；因此移动目录前应先退出托盘，复制目录等同于复制其本地运行数据，删除目录也会删除 portable 数据。

portable 不读取 MSI 的 `%LocalAppData%\AutoDy` 作为自身 DataRoot，也不会依赖已安装 AutoDy。若同机同时存在 MSI 与 portable，应分别从各自入口启动，并通过服务身份确认当前页面来源；不要让两个实例并发操作同一浏览器或计划任务。

## 8. Repair、升级、卸载与重新安装

Repair：在 Windows 设置的应用页面或 MSI 维护界面选择 Repair。预期是程序 payload 和快捷方式被恢复，%LocalAppData%\AutoDy 数据不被清空；若 Repair 失败，收集 MSI verbose log 后停止，不要删除数据目录。

从 1.4.0–1.4.2 迁移：这些版本是 per-user，而 1.4.3 是 per-machine，Windows Installer 不能直接跨范围完成 MajorUpgrade。先在同一 Windows 用户下从 Windows 设置卸载旧 AutoDy 程序，确认 `%LocalAppData%\AutoDy` 仍在，再运行 1.4.3 MSI。新 MSI 检测到旧 per-user 登记时会拒绝并存。不要手动删除 DataRoot 或 Windows Installer 注册信息。

卸载：可从 Windows 设置的应用管理页卸载，也可用开始菜单“卸载 AutoDy”快捷方式。预期是三个 AutoDy Windows 计划任务、程序文件和快捷方式移除；`%LocalAppData%\AutoDy` 中的计划设置、历史、受管资料和备份默认保留。重新安装会用保留的配置重新创建任务，不会自动公开或上传数据。只有用户明确确认永久放弃资料并已退出受管理服务后，才考虑处理该单一数据目录。

## 9. 用户可见错误与安全提示

安装包提示未签名或受到 Windows 信任策略限制时，应核对发布来源和 SHA-256，并咨询组织策略；不要使用 UPX、关闭终端防护或下载来源不明的 DLL。D3DCompiler_47.dll 写入/载入问题先检查磁盘空间、文件哈希和安全软件隔离记录，然后使用 Repair。关于端口、快捷方式、登录、安装路径或排程的具体诊断见 05-运维维护与故障排查。

## 10. 操作结果对照表

| 操作 | 正常结果 | 异常时首先做什么 | 不应做什么 |
| --- | --- | --- | --- |
| 首次安装 | 程序目录创建，数据目录独立。 | 检查目录可写与包哈希。 | 删除现有数据目录。 |
| 打开管理台 | 托盘打开 127.0.0.1:<selected-port>。 | 从托盘再次打开并记录端口。 | 按名称结束所有进程。 |
| 重复启动 | 复用同一 AutoDy PID。 | 查看服务身份失败提示。 | 因“已运行”强制杀进程。 |
| 登录恢复 | 在受管窗口恢复本机会话。 | 检查登录状态和页面异常。 | 导出 Cookie 或复制日常 profile。 |
| 管理定时任务 | 单次 UAC 后刷新 Windows 任务状态。 | 核对 UAC 是否取消及页面错误摘要。 | 永久以管理员运行 Dashboard。 |
| Repair | 恢复程序和快捷方式。 | 保存 verbose log。 | 把 Repair 当作删除数据。 |
| 卸载 | 移除程序、快捷方式和 Windows 任务，保留用户数据。 | 从 Windows 设置执行维护。 | 随意删除 %LocalAppData%。 |
| 启动 portable | 解压后运行 `AutoDy.cmd`，数据留在解包目录。 | 检查是否完整解压且目录可写。 | 从 ZIP 内运行或另装系统 Python。 |

安装后如需迁移，先确认是要迁移程序目录还是数据目录。程序目录由 MSI 维护，推荐通过新的安装/维护流程改变；数据目录含计划和受管资料，不应通过复制到公开位置完成“迁移”。任何要交给支持人员的材料应只包含经脱敏的版本、错误阶段和日志摘要，不包含个人运行时资料。

## 11. 安装前后自检清单

安装前确认来源、版本、SHA-256、磁盘空间和可写目录。安装后确认开始菜单或桌面入口存在、托盘能够显示、Dashboard 可由托盘打开、页面没有要求复制浏览器资料。升级前确认当前任务不在受管理执行中；升级后确认历史与计划仍可见、端口由托盘正确打开。任一检查不符合预期时，停止下一步操作并转到运维手册，不要用重装覆盖问题。
