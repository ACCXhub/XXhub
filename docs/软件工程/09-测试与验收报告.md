## 8. 高风险边界的已定义验收

### 8.1 发送

必须证明：stable binding/account scope/locator 一致；browser lock 存在；同日成功不重复；send_attempts=0 的 safe failure 才可 retry；确认不确定进入 `uncertain` 且无自动 retry。

### 8.2 服务恢复

必须证明：unknown listener 不停止；managed service 才可重启；process exists + health 短暂失败不立即恢复；强停前重新验证 exact PID；10 分钟 3 次后熔断；manual full exit 有 suppression；自动恢复不会触发业务发送/扫描/Scheduler repair。

### 8.3 安装

必须证明：ProgramRoot/DataRoot 分离；原用户 Principal/DataRoot 跨提升正确；fresh/Repair/custom/upgrade/uninstall 均符合预期；卸载删除 AutoDy tasks/程序但保留 DataRoot；上一稳定 baseline 升级不丢数据。

当前 v1.5.0 正是在这一最后 lifecycle 组合验收上尚未闭环。

## 9. 未覆盖/不能过度推断的范围

- 所有 Windows 版本、企业策略、安全软件和代理组合；
- Douyin 未来页面/React model 变化；
- 所有网络/登录有效期边界；
- 未签名 MSI 在不同组织的 SmartScreen/策略体验；
- 真实发送压力/批量行为（测试不得通过真实账号发送来获得覆盖）。

自动化通过不等于平台永不变化；发布门禁的作用是证明当前输入和环境下的关键契约。

## 10. 当前退出条件

v1.5.0 只有在以下条件同时成立后才能更新为“正式稳定 Release”：

1. 明确 lifecycle report 的失败项；
2. 修复真实 installer defect 或错误 verifier assertion 的 canonical owner；
3. 在最终 release source/tag 上重新执行正式 Release workflow；
4. lifecycle 全绿；
5. canonical MSI/Portable/checksum/manifest 发布；
6. public asset re-download/hash/MSI/privacy 全绿；
7. README/CHANGELOG/RELEASE_NOTES/本报告同步切换为“已发布”。

在此之前，v1.4.4 保持公开稳定基线，v1.5.0 保持候选状态。
